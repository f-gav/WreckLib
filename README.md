# WreckLib

Независимая энциклопедия кампаний. Отдельный репозиторий и **отдельный проект Supabase**. Никаких изменений в WreckTrack / At your service!.

## Статус

Миграция с Cloudflare на Supabase в работе. Клиент использует Supabase Auth (OTP по email), PostgreSQL, RLS и приватный Supabase Storage. Предыдущие `worker/`, `wrangler.jsonc`, `migrations/0001_init.sql` оставлены пока как исторические черновики и **не предназначены для запуска**. Развёртывание не выполнено.

## Первый запуск

1. Создайте **новый проект Supabase** в отдельной организации/аккаунте (на текущем аккаунте уже заняты два бесплатных проекта).
2. В SQL Editor нового проекта выполните `supabase/001_init.sql` — **не выполнять в проектах WreckTrack или At your service!**.
3. В `public/config.js` впишите только `Project URL` и `publishable key` нового проекта; никогда не вставляйте `service_role` или secret key.
4. В разделе Auth настройте Site URL и Redirect URLs для отдельного адреса WreckLib. Email OTP/Magic Link должен быть разрешён.
5. Разместите содержимое `public/` в отдельном статическом хостинге (например, GitHub Pages с отдельным репозиторием) и откройте сайт.
6. Перед публичным запуском проверить RLS на трёх пользователях разных кампаний и отсутствие доступа к секретам/изображениям.

## Функции на текущем этапе

- Независимые кампании, Мастер, Игрок+, Игрок.
- Вложенные папки и карточки; скрытые карточки и секреты в отдельной таблице.
- Приватное хранение изображений WebP с клиентским сжатием.
- Приглашение по ссылке для конкретного email.
- Минималистичный адаптивный интерфейс, вдохновлённый WreckTrack.

Строгая интеграционная проверка прав (в том числе обновления полей и обходов иерархии), защита от гонок изменений, журнал ревизий, корзина, резервное копирование, Markdown, освобождение неиспользуемых файлов и настройка CI/deploy. Этот код — прототип, не production-ready.
