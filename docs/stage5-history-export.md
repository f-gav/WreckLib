# WreckLib — этап 5A: история карточек и JSON-экспорт

## История
- Миграция `supabase/014_entry_history.sql`, отдельная закрытая таблица `private.entry_revisions`.
- После создания карточки формируется версия 1, после каждого содержательного изменения названия, описания, Markdown или тегов формируется следующая версия.
- Движение по папкам, удаление в корзину, смена видимости и замена изображения не создают контентные версии.
- Только Мастер имеет доступ к трём защищённым RPC: `list_entry_revisions`, `read_entry_revision`, `restore_entry_revision`.
- Игрок+ может редактировать опубликованную карточку, но не просматривать исторический контент: раньше карточка могла содержать скрытую информацию.
- История не включает `entry_secrets` (заметки Мастера), файлы изображений, `image_path`, удаление, `visibility` и `parent_id`.
- Восстановление откатывает только название, описание, тело и теги; существующие заметки Мастера, видимость и папки остаются без изменений.
- Восстановление записывает новое состояние как отдельную версию; старые версии остаются доступными.
- Удалённые/скрытые от клиента карточки не открывают RPC истории. Безвозвратное удаление карточки удалит и её историю через FK CASCADE (безвозвратное удаление пока не реализовано).
- В интерфейсе у Мастера появилась кнопка «История версий» с выбором, безопасным предпросмотром и подтверждением отката.

## Экспорт JSON
- На странице кампании у Мастера доступна кнопка «Экспорт JSON».
- Клиент повторно проверяет серверные права через `list_campaign_members` и загружает текущие записи через действующий RLS, постранично (500).
- Для каждой партии записей загружаются заметки Мастера из `entry_secrets`. Ошибка прав или выгрузки прерывает экспорт.
- Формат: `WreckLib`, `schema_version:1`, ID кампании, имя, `entries` с ID, `parent_id`, типом, текстом, Markdown, тегами, видимостью, путём изображения и секретными заметками.
- JSON создаётся локально в браузере; ключи сервиса, токены и гостевые ссылки не экспортируются.
- Экспорт не является полной резервной копией: отсутствуют бинарные изображения, удалённые записи из корзины, история ревизий и назначения ролей. Импорт из этого файла ещё не реализован.
- Формат специально ограничен и версионирован для последующего инструмента импорта.

## Проверка
- CI Node: `tests/stage5-export.test.js` и `tests/stage5-integration.test.js`; проверка клиентских файлов и опасного контента.
- PostgreSQL: `tests/stage5-history-smoke.sql`, транзакция с ROLLBACK; проверка ограничений Мастера/Игрока+/Игрока/постороннего, старой скрытой версии, запрета кросс-отката, неизменности заметок/структуры, новой версии после отката.
- Регрессии 3B–4B: SQL-наборы для тегов, корзины, иерархии, приглашений и Storage повторно пройдены.
- Supabase Security Advisor выполнен. Остаются прежние предупреждения: намеренно callable definer RPC, отключённая leaked-password protection и закрытые таблицы с RLS без политик. Перед общедоступным релизом нужен полный аудит.
- GitHub Pages smoke после merge проверит `export.js` и другие публичные ресурсы.

## Не подтверждено
- Реальный браузерный E2E на двух Google-аккаунтах и с пользовательскими данными; в живой базе нет кампаний и записей.
- Полная резервная копия изображений и импорт JSON.
- Разрешение конкурентного редактирования/история изменений секретных заметок.

## Принцип
Все изменения только в выделенном репозитории f-gav/WreckLib и его отдельной базе Supabase. WreckTrack не менялся.
