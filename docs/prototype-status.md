# WreckLib — контрольная точка · 25 октября 2026

## Состояние
- Репозиторий: `f-gav/WreckLib`; сайт: https://f-gav.github.io/WreckLib/.
- База: отдельный Supabase `nwlthntpkmgrhmejhfqk`. **WreckTrack не менять**.
- Google OAuth: конфигурация провайдера включена и серверный callback/redirect работает. В базе появилась Google-identity существующей учётной записи. Пользователь сообщил, что проверил реальные Google-аккаунты; самостоятельное browser E2E двух аккаунтов через инструменты не проводилось.
- Фронтенд развёрнут GitHub Pages; CI проверяет исходники и доступность опубликованного сайта, шрифтов и стартового OAuth.
- Роли `master`, `editor`, `viewer` существуют в БД; гости без аккаунта читают только по 256-битной отзы́вной ссылке.
- Скрытые материалы и секреты доступны только Мастеру; изображения остаются в приватном Storage.
- Визуальный стиль: базовые CSS-токены WreckTrack, четыре цветовых акцента, пять шрифтов, мобильный переключатель «Разделы / Статья».
- Серверные тесты SQL выполнялись внутри `BEGIN … ROLLBACK`, без сохранения фиктивных пользователей.

## Завершено на этом проходе
1. Проверено наличие Google identity наряду с email identity в `auth.identities`, без раскрытия персональных сведений.
2. Транзакционными проверками подтверждено: приглашение может принять только нужный email; роль Игрок+ допускает создание записей; Игрок не получает права на изменение.
3. Миграция `006_safe_entry_moves.sql`:
   - повторное приглашение **не переписывает** существующую роль;
   - безопасный RPC `move_entry`, ограниченный ролью;
   - запрет циклической вложенности, пересечения кампаний и скрытых папок для редакторов.
4. UI: кнопка «Переместить», диалог выбора папки, раскрытие/сворачивание дерева и сортировка «папки впереди».
5. Миграция `007_unused_image_cleanup.sql`: автор может через Storage API очищать **собственные неиспользуемые** файлы; чужие и привязанные изображения защищены. SQL-тест проверяет RLS/видимость и наличие DELETE-политики. Прямое SQL DELETE заблокировано встроенным триггером Supabase Storage и не должно использоваться.
6. Актуальные CI и Deploy проверены после обеих миграций и изменений интерфейса.

## Важные ограничения проверки
- В момент последнего анализа живой проект содержал Google identity, но **не содержал кампаний, приглашений или изображений**. Реальное сохранение и отправку WebP между настоящими пользователями нельзя подтвердить только по схеме.
- Положительный тест скачивания реального WebP через Edge Function `shared-image` требует существующего опубликованного изображения и действующей гостевой ссылки. Отрицательный тест с неверным токеном уже пройден.
- Ручной сценарий: войти Google; создать кампанию; создать папку/статью; загрузить WebP; перезагрузить; пригласить второй аккаунт Игрок+; проверить изменение и перемещение; проверить просмотр из инкогнито; затем отозвать ссылку.
- Политики и структурные RPC защищают базу. Browser E2E, визуальное тестирование на устройствах и нагрузочные тесты больших деревьев пока остаются в плане.

## Безопасность и процесс
- Не использовать исторические файлы Cloudflare.
- Любые изменения Supabase только в проекте WreckLib. Никогда не публиковать `service_role` или Google Client Secret в клиенте/репозитории.
- После каждого изменения: dry-run миграции, rollback smoke, npm CI, Pages deploy, сверка логов и запись новой контрольной точки.
