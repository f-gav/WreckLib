# WreckLib 5B — безопасный импорт, изображения и конкурирующее редактирование

## Новый импорт JSON
- После выбора файла интерфейс локально проверяет `schema_version: 1`, название кампании, структуру, ID, вложенность папок, поля, теги, размеры текста и подписи WebP.
- Показывается предварительное резюме: название, число карточек/папок и изображений. До нажатия «Создать кампанию из архива» записи не меняются.
- Импорт всегда создаёт **отдельную кампанию**, никогда не перезаписывает существующую.
- `public.import_campaign_snapshot` ограничивает JSON 3 МБ и 250 записями, проверяет целостность дерева и создает кампанию/все карточки/секретные заметки атомарно в транзакции. Старые ID переводятся в новые UUID, связи `parent_id` перестраиваются.
- Неправильная иерархия, превышение лимитов или конфликт ограничений приводит к полному откату SQL.
- Импорт доступен вошедшему пользователю и создаёт ему собственную новую кампанию с ролью Мастера. Анонимные гости импортировать не могут.

## Резервная копия с изображениями
- В WreckLib есть два вида выгрузки: базовый JSON и расширенный JSON с приватными WebP.
- Расширенный архив формируется **в браузере** из файлов, которые Мастер вправе скачать из `wrecklib-images`. Изображения кодируются base64 внутри `image_assets`.
- Лимиты: 3 МБ на изображение, до 24 МБ бинарных данных изображений, общий JSON до 36 МБ.
- Загруженные изображения проверяются по WebP RIFF-сигнатуре ещё до подтверждения импорта.
- После атомарного импорта текста каждый WebP отдельно загружается в новый приватный Storage с новым путём, а путь назначается через защищённую RPC `attach_entry_image_if_unchanged`.
- **Ограничение:** загрузки Storage не входят в SQL-транзакцию. При сбое частично восстановленные изображения могут потребовать повторной загрузки; сами карточки не стираются, и интерфейс сообщает количество уже восстановленных файлов.
- Старые JSON-архивы 5A без `image_assets` тоже допустимы — импортируют текст и структуру без изображений.

## Защита параллельных редакторов
- `public.update_entry_if_unchanged` сверяет ожидаемое `updated_at` под блокировкой строки. Если другое окно или редактор изменили карточку, сервер сообщает `EDIT_CONFLICT`; пользовательские несохранённые изменения остаются в открытом редакторе.
- Заметки Мастера обновляются тем же атомарным RPC. Игрок+ не может менять скрытые заметки и видимость.
- `public.attach_entry_image_if_unchanged` проверяет версию карточки, её видимость, роль и принадлежность файла загрузившему пользователю.
- `touch_entry_updated_at` использует монотонное микросекундное время; совпадения в пределах SQL-транзакции исключены.
- Прямой `UPDATE` таблицы `entries` у клиентской роли отозван. Импорт, перемещение, корзина, версии и вложения используют защищённые серверные операции.
- Версия 5B намеренно **отклоняет конфликт**, а не пытается объединить Markdown автоматически.

## Проверки
- Тесты модулей `tests/stage5b-import.test.js` и UI `tests/stage5b-ui.test.js` запускаются в Node CI.
- `tests/stage5b-db-smoke.sql` проверяет импорт, сохранность секретных заметок, UUID-переназначение, циклы и атомарность, RPC и ошибку старой версии, запрещённый прямой UPDATE, привязку изображений и роли. Все тестовые данные откатываются.
- Дополнительно регрессионные SQL наборы этапов 3B–5A.
- GitHub Pages публикуется только после зелёного CI, smoke проверяет `import.js`.
- Security Advisor проверяется до публикации. Прежние предупреждения о PUBLIC SECURITY DEFINER и leaked-password protection остаются вопросами финального релизного аудита.

## Не входит
- История заметок Мастера и изображений, версиями сохраняется лишь текст карточек и теги.
- Полностью транзакционный откат Storage при сбое загрузки.
- Объединение параллельных правок или синхронизация на нескольких вкладках.
- Browser E2E с двумя реальными Google-аккаунтами: действующая база остаётся без кампаний и материалов.

**Изоляция:** WreckTrack не изменяется; используется отдельный Supabase проект WreckLib.
