# WreckLib — этап 4A: Markdown, поиск и перекрёстные ссылки

## Реализация
- Вся механика добавлена **только** в WreckLib. Оригинальный WreckTrack не менялся.
- Markdown хранится в прежнем поле \`entries.body\` (текст). Не требуется менять схему Supabase, копировать данные или давать новые права в RLS.
- Поддерживаемая версия Markdown: заголовки H1–H6, жирный, курсив, зачёркнутый текст, абзацы, списки, цитаты, разделители, встроенный код и ограждённые блоки кода, внешние HTTPS/HTTP ссылки.
- HTML из статей не исполняется, а экранируется. Ссылки имеют \`rel="noopener noreferrer"\`. Исполняемые или небезопасные URL не создаются.
- В редакторе кнопки форматирования, выбор статьи для вставки ссылки, живой предпросмотр. Исходный текст всегда можно редактировать напрямую.
- В просмотре доступна разметка Markdown вместо сырого текста. Старые записи остаются читаемыми как обычные абзацы.

## Вики-ссылки
- \`[[Название статьи]]\` — ссылка по названию. При совпадении нескольких видимых названий считается неоднозначной и не активируется.
- \`[[UUID|Отображаемый текст]]\` — стабильная ссылка, в том числе при последующем переименовании.
- Выбор статьи в редакторе вставляет стабильный UUID-вариант.
- Ссылка кликабельна только если целевая статья присутствует в \`entries\`, уже полученных через существующий RLS (участники) или гостевой RPC с проверкой токена.
- Нельзя открывать произвольную UUID по ссылке или запрашивать по ID скрытые и удалённые записи.
- Обратные ссылки вычисляются только по доступным статьям на экране.

## Поиск
- Поиск по названию, описанию и содержимому доступных материалов, без дополнительных SQL RPC и привилегий.
- Работает в обычном режиме и в гостевом режиме только по опубликованным данным, которые уже вернул сервер.
- Поиск локальный и удобен на этапе прототипа. Для десятков тысяч статей понадобится отдельный полнотекстовый индекс с RLS-aware API.
- Секретные заметки Мастера в \`entry_secrets\` в поисковый индекс не входят.

## Проверки
- \`tests/markdown.test.js\`: HTML/XSS, Markdown, фильтрация вики-ссылок, обратные ссылки, неоднозначные названия, небезопасные URL.
- \`tests/stage4-integration.test.js\`: подключение кнопок и форм, поиск исключительно в разрешённых записях, сохранение оформления WreckTrack.
- Rollback SQL smoke этапа 3B повторно пройдены до внесения изменений.
- В CI запуск \`npm run check\` и \`node --check public/app.js\`.
- После публикации smoke GitHub Pages дополнительно проверяет \`markdown.js\`.

## Что не входит в этап 4A
Полный CommonMark/GFM (таблицы, изображения Markdown, вложенные списки), совместное редактирование с разрешением конфликтов, серверный full-text индекс, полноценная система тегов, история версий, browser E2E под двумя реальными Google-аккаунтами.

## Важный порядок проверки
Сначала CI на feature-ветке, только после успешного результата — merge в main и GitHub Pages deploy. Изменения не должны публиковаться раньше прохождения тестов.
